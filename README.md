# rvc-key-finder

[English](README.en.md) · 中文

**RVC 翻唱定调助手 —— 双引擎交叉验证，自动给出正确的降调量。**

一个在 RVC 翻唱圈里**别人都没做、只有这里做了**的小工具：
同时「测源音频」和「读模型权重」，两条独立路线互相印证。

---

## 一句话说清它解决了什么

用 RVC 做 AI 翻唱，第一步永远是「定降调量」——原唱音高要降几个半音，
才能落进你的声音模型的舒适音区。**这一步错了，后面全白费。**

但几乎所有教程、所有现成的翻唱项目（AICoverGen、xinxin-song、RVC-dstts、
Ultimate RVC……）都是这么干的：

> 用 RMVPE / crepe 跑出 f0 → **人眼看一下中位数 → 手动拍脑袋定「降 5 还是降 8」**。

这里藏着两个**没人认真处理的坑**：

### 坑①：自相关（autocorrelation）在 60~1200Hz 全范围找峰时，会**误判八度**

- 男声的**倍频（2f0）**周期性往往比基频还高 → `argmax` 落在倍频上 → 把男声误判成高八度的女声
- 女声的**次谐波（f0/2）**有时也会抢峰 → 把女声误判成低八度的男声

结果就是：**定出来的降调量错一倍**。本该降 8，可能定成降 12 甚至 0，
整首歌唱出来不是刺耳破音，就是闷得听不清。

**这个坑，我真实踩过。** 一个真实案例：

> 邓紫棋《Where Did U Go》，自相关在低范围找到 175Hz，看着像男声。
> 但频谱能量裁决发现 **350Hz 处的能量是 175Hz 的 385 万倍** ——
> 175Hz 只是次谐波，350Hz 才是真基频（女声）。
> 正确结论是降 8 半音，而不是被 175Hz 误导。

### 坑②：模型音域靠「猜」，没人直接读权重

你的声音模型到底练过哪些音高？几乎所有人都靠"听素材、估个上限"。
但其实**答案就写在模型权重里**——RVC 的 pitch embedding 表记着训练时见过哪些音。

## 别人没做、这里做了的事

| 现有翻唱项目 | 本项目 |
|---|---|
| f0 跑出来直接看中位数 | **双范围交叉验证**：60-250Hz 和 60-1200Hz 两个范围分别找峰 |
| 倍频/次谐波误判没人管 | **频谱能量裁决**：直接比「f0」和「2×f0」的能量，谁强谁是基频 |
| 降调量全靠人拍脑袋 | **自动给降调建议**：结合你的声音模型素材上限，算到偶数半音 |
| 模型音域靠"听素材估" | **读权重**：pitch embedding 差分，直接读出模型练过的音区 |

前两件在 RVC 翻唱这个细分场景里，**我搜遍 GitHub 没找到第二个人做过**。
（通用音高检测领域有 octave-correction 的学术研究和工具，但没人把它用到
「RVC 翻唱定档」这个具体痛点上。）

而「读权重定音域」这条路线，业界只有极少数人在探索——本项目把它和
「源音频定档」**合二为一，交叉验证**，这是别处没有的组合。

## 快速开始

```bash
pip install numpy soundfile soxr

# 【双引擎】源音频定档 + 模型音域，交叉验证
python key_finder.py --vocal vocals.wav \
    --model 我的模型.pth --base 底模.pth --material-max 375

# 【单引擎】只测源音频（不读模型权重）
python analyze_pitch.py --vocal vocals.wav --material-max 375

# 【单引擎】只读模型音域
python tools/read_pitch_range.py --model 我的模型.pth --base 底模.pth
```

- `--material-max` 是你声音模型训练素材的**最高舒适音（Hz）**（本项目实测约 375Hz）
- `--model` + `--base` 是引擎②，需要 torch；不给也能用引擎①

输出示例（双引擎）：

```
【引擎① 源音频定档】
频谱能量裁决: 2×低范围/低范围 = 3561629.2 倍
  -> 350 Hz 是真实基频（低范围是次谐波误判，女声常见）
★ 推荐定档: -8 半音

【引擎② 模型音域】
训练槽: 127 / 256 个 → 音区 53 ~ 940 Hz

交叉验证：源基频 350 Hz 落在模型音区内，一致。
```

## 算法原理（30 秒看懂）

### 引擎① 源音频定档（防八度误判）

1. **FFT 加速自相关**逐帧找基频（`np.correlate` 是 O(n²)，FFT 后 <10ms）
2. **两个频率范围**各找一次峰：60-250Hz（低）、60-1200Hz（全）
3. 两者相差约 2 倍 → 触发**频谱能量裁决**：
   - `2×f0` 能量显著更强 → 低范围是次谐波，真基频在 2 倍处（女声）
   - `f0` 能量显著更强 → f0 就是基频（男声）
4. 拿到真实基频的 95 分位 → 反推要降几个半音，落到素材上限内

### 引擎② 模型音域（读权重，不测音频）

RVC 用一张 256 槽的 **pitch embedding**（`emb_pitch`，256×hidden）编码音高，
槽位按 Mel 频率量化（50~1100Hz）。训练时只有唱到的音高，其向量才会相对底模移动。
把「模型」和「底模」逐槽做差，动过的槽就是「训练见过的音高」= 模型音域。

两条路线**互相独立、互补**：引擎①可能八度误判，引擎②不测音频、无此问题；
引擎②读出的是"见过哪些音高"，引擎①的素材上限可收窄成"舒适音区"。
