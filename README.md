# rvc-key-finder

[English](README.en.md) · 中文

给 RVC 翻唱算降调量的一个小工具。

做翻唱的时候，第一步总是要先定：原唱的音要降几个半音，才能落到自己声音模型舒服的区间。这个数定错了，后面全白搭。这个工具就是帮我（也帮你）把这一步做对。

---

## 它解决什么问题

现在大家做 RVC 翻唱，定调基本都是这样的：用 RMVPE 之类跑出 f0，看一眼中位数，然后凭感觉填一个"降 5"或者"降 8"。这中间有两个容易踩的坑。

### 坑一：自相关找峰容易找错八度

在 60~1200Hz 这个范围里用自相关找峰，有时候会找到倍频或者次谐波上：

- 男声的倍频（2f0）周期性经常比基频还强，`argmax` 就落在倍频上，男声被当成高八度的女声；
- 女声的次谐波（f0/2）偶尔也会抢峰，女声被当成低八度的男声。

结果就是降调量差了一个八度。本该降 8 的，可能填成降 12 或者 0，唱出来要么破音要么发闷。

我自己就踩过。拿邓紫棋的《Where Did U Go》试的时候，低范围找到 175Hz，乍一看像男声；后来用频谱能量一对比，350Hz 的能量是 175Hz 的 385 万倍，说明 175Hz 只是次谐波，350Hz 才是真基频。正确的降调量是 8。

### 坑二：模型音域全靠猜

自己的声音模型到底练过哪些音，一般就是听一听素材、估一个上限。其实这个信息就写在权重里：RVC 用一张 256 槽的 pitch embedding 记音高，训练时唱到过的音，对应的向量才会相对底模移动。把模型和底模的这张表逐槽做差，就能看出模型练过哪些音。

---

## 做了什么

- 定调的时候，在 60~250Hz 和 60~1200Hz 两个范围分别找峰，互相印证；
- 两个结果差大约两倍的时候，比一下 f0 和 2×f0 的频谱能量，谁强谁是基频；
- 结合素材上限，自动给一个偶数半音的降调建议；
- 另外可以直接读模型权重，把模型练过的音域读出来，跟上面的结果对一下。

前三条是我在 RVC 翻唱这个场景里没找到现成实现的；读权重这条，业界有个别闭源软件做过类似的事，这里是开源的实现，而且把它跟源音频定调放在一起用。

## 用法

```bash
pip install numpy soundfile soxr

# 两个都用：源音频定调 + 读模型音域
python key_finder.py --vocal vocals.wav \
    --model 我的模型.pth --base 底模.pth --material-max 375

# 只用源音频
python analyze_pitch.py --vocal vocals.wav --material-max 375

# 只读模型音域
python tools/read_pitch_range.py --model 我的模型.pth --base 底模.pth
```

`--material-max` 是模型素材里最高的舒服音（Hz），我自己的模型大概 375。
`--model` 和 `--base` 一起给才读权重，需要 torch；不给也能只用源音频那条。

输出长这样：

```
【源音频定调】
频谱能量裁决: 2×低范围/低范围 = 3561629.2 倍
  -> 350 Hz 是真实基频（低范围是次谐波）
推荐定档: -8 半音

【模型音域】
训练槽: 127 / 256 -> 53 ~ 940 Hz

交叉验证：350 Hz 落在模型音域内，一致。
```

---

## 原理

### 源音频那条

1. FFT 加速自相关，逐帧找基频；
2. 两个范围各找一次峰；
3. 差大约两倍时，比 f0 和 2×f0 的能量定谁是基频；
4. 拿真基频的 95 分位，反推降几个半音。

纯 numpy，不用装 RMVPE/Applio。

### 读权重那条

RVC 的 pitch embedding 是 256 槽，Mel 量化（50~1100Hz）。把模型和底模逐槽做差，动过的槽就是练过的音高。

两条路独立、互补：源音频那条可能找错八度，读权重那条不碰音频没这个问题；反过来，读权重只能告诉你"练过哪些音"，不一定是"唱得舒服的音"，这个得靠素材上限来收。
