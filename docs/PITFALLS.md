# PITFALLS —— AI 翻唱避坑大全

每一条都来自真实翻车 + 修复后的实测数据。
按"影响大小"排序。

## 一、源准备

### 1.1 副歌/高潮段"唱得乱" → 九成是和声，不是参数
- **现象**：某一段音高东倒西歪、RVC 唱到八度外。
- **误诊**：反复调 index/protect/f0_method——实测六组参数在该段的
  谐波度差异 <2%，**根本不是参数问题**。
- **真因**：原唱的**和声叠层**全部混进人声轨，RVC 同时"听到两个人唱"。
- **修法**：用 UVR 的 Karaoke 模型（`5_HP-Karaoke-UVR.pth`）把和声剥进伴奏。
- **实测**：问题段中位周期性 **0.47 → 0.71**，低周期占比 **50% → 17%**。
- **验证脚本**：`tools/periodicity_scan.py`

### 1.2 静音段被硬切 → "突然啊一下" + 宽带杂音
- **现象**：人声整段突然消失又突然冒出，伴随咔哒。
- **真因**：置零逻辑算出了淡化长度却没用（`env = np.zeros(...)`），
  产生 1460 个精确零窗、210dB 电平跳变。
- **修法**：不切绝对零，**沉到 −30dB**；过渡用 **500ms smoothstep**；
  所有衰减/退让的边界一律 smoothstep，绝不线性硬切。
- **实测**：绝对零窗 **1460 → 0**，最大跳变 **210 → 26.6 dB**。
- **检测**：`tools/find_glitch.py`（幻觉/突变/突响三类扫描）。

## 二、定档（降调量）

### 2.1 倍频/次谐波误判 → 降调量错一倍
- **现象**：男声被当女声，错降 12 半音压到 82Hz。
- **真因**：自相关在 60–1200Hz 全范围找峰，男声的**倍频**（2f0）周期性
  往往更高，argmax 落在倍频上。
- **修法**：**双范围交叉验证**——同一帧分别在 60–250Hz 和 60–1200Hz 找峰：
  - 两结果接近 → 可信；
  - 高范围 ≈ 2×低范围 → 取低范围（男声被倍频）；
  - 拿不准 → 用**频谱能量**裁决：真基频所在频带能量应显著强于其半频处
    （实测一例：350Hz 处能量是 175Hz 的 385 万倍 → 350 是基频）。
- **教训**：**降调量是全局决策，错一次全曲报废**，值得多花两分钟验证。

### 2.2 "降得越多越安全"是错觉
- 降太多 → 副歌掉到 200Hz 以下，闷、没有冲击力。
- **判据**：降调后**副歌 70 分位落在 250–320Hz**、全曲 95 分位 ≤ 素材上限。

## 三、RVC 推理参数

### 3.1 protect 语义（最容易搞反的一条）
官方 FAQ：**0.0 = 最大保护**（更多保留原始清辅音），**0.5 = 不保护**。
- 唱歌要咬字清楚：**0.05–0.20**（本项目用 0.10）。
- 官方默认 0.33 是为语音设计的折中值，唱歌会糊。

### 3.2 volume_envelope 不跟源 → 忽大忽小
- **现象**：句间突然掉到 −82dB，像"唱不出来"。
- **真因**：`volume_envelope=1.0` = 完全听模型自己的音量包络，
  有些模型句间会自我衰减。
- **修法**：**0.4**（主要跟随源）。实测与源的电平偏差 **9.3 → 5.0 dB**。

### 3.3 index_rate 的黄金区间
0.4–0.6。低于 0.3 原声音色残留，高于 0.7 金属感/机械音。
本项目 0.50。

### 3.4 f0 算法
rmvpe 默认；素材周期性低时可试 crepe（抖动实测 8.4→7.6 音分），
但**先用 1.1 的去和声解决根源**，算法只是锦上添花。

## 四、后期混音

### 4.1 混响必须高通返回（咬字清晰的头号开关）
低频混响是"糊"的主因。板式混响的返回链路先过 **300Hz 高通**，
湿量 **10–15%**、预延迟 **30–40ms**、衰减 1.5s 左右。
加了高通后，混响可以开得更有空间感而不糊。

### 4.2 并行压缩（提密度不糊辅音）
干净支（串行 3.2:1 慢起音）+ 狠压支（8:1 快起音）按 **72% / 28%** 混合。
比单级重压更透。

### 4.3 de-esser 放压缩**之后**
压缩会放大齿音，此时处理更透明。6.8–7k，宽 Q，−1.5~−2dB。

### 4.4 loudnorm 单遍 = 动态模式 = 灾难
- **现象**：轻的前奏被抬高 **+28dB**，整曲动态关系全毁。
- **修法**：先 `loudnorm=print_format=json` 测出 input_i，
  再 `volume=XdB` **线性平移** + alimiter。动态原样保留。

## 五、工程

### 5.1 自相关必须用 FFT 加速
`np.correlate` 是 O(n²)：297 秒的歌逐秒打分要 **20 分钟**；
换 FFT 自相关 → **3 分钟**。任何逐窗分析脚本都要注意。

### 5.2 分段拼接是电音之源
两套参数逐秒择优拼接（133 段）→ 音色在接缝处跳变，听感就是"漏电"。
**单一参数整轨贯穿**，需要退让就用平滑包络，不要切换音色。

### 5.3 低配显卡的可行边界
6GB（如 CMP 30HX）：BS-RoFormer(639MB) **跑不动**（卡死在显存溢出后的
CPU 回退）；VR 架构模型（5_HP-Karaoke 127MB）2.5 分钟可跑完。
